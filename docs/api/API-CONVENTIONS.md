# API conventions

The API uses URL-segment versioning. `GET /api/v1/health` is process liveness, `/health/ready` checks configured database dependencies, and `POST /api/v1/contact-inquiries` validates and persists public contact inquiries. Identity endpoints live under `/api/v1/auth`; `GET /api/v1/users/me` requires a bearer token. Contact and liveness routes are explicitly anonymous. The contact endpoint returns 201 on persistence, 400 for invalid fields, and 429 when its per-IP rate limit is exceeded. The API uses ProblemDetails for unhandled errors and serves OpenAPI only in Development. Business endpoints must use explicit authorization policies, tenant checks, DTOs, validation, and documented status/paging/filtering contracts; never return EF entities.
