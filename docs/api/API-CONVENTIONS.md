# API conventions

The API uses URL-segment versioning. `GET /api/v1/health` is process liveness, `/health/ready` checks configured database dependencies, and `POST /api/v1/contact-inquiries` validates and persists public contact inquiries. Identity endpoints live under `/api/v1/auth`; `GET /api/v1/users/me` requires a bearer token. Authenticated organization routes create an organization with owner membership, list only the caller's organizations, and resolve `/api/v1/organizations/current` only after checking the `X-Organization-Id` selector against active membership. Contact and liveness routes are explicitly anonymous. The contact endpoint returns 201 on persistence, 400 for invalid fields, and 429 when its per-IP rate limit is exceeded. The API uses ProblemDetails for unhandled errors and serves OpenAPI only in Development. Every future tenant-owned endpoint must require authenticated membership and scope each read/write by the verified `IOrganizationContext`; never trust the header alone or return EF entities.
