## Integration rules

- Keep API origin normalization in `dashboard/src/app/core/api-url.ts`; do not create per-feature API base URL logic.
- Keep organization IDs sourced from the signed-in membership list. The API remains responsible for verifying the `X-Organization-Id` header on every tenant-scoped request.
- Use backend role and membership responses to control the interface, but treat all UI checks as presentation only. Backend authorization remains authoritative.
- Keep dashboard API DTOs aligned with response records in `CrmEndpoints`, and test exact route paths for non-obvious resource names.
- Do not add sample business records to make unimplemented screens appear live. Implement the domain/API lifecycle first, then connect the route.
